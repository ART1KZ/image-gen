# Parallel tab jobs implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development
> or executing-plans to implement this plan task-by-task.

**Goal:** Choose ChatGPT tabs and run isolated image jobs concurrently through
both a CLI and MCP, with shared job ownership, cancellation and recovery.

**Architecture:** One authenticated local IPC coordinator per browser profile
owns a scheduler and a CDP browser adapter. CLI and MCP are clients of the same
service. Each job owns a tab reservation, immutable artifact and output path.

**Tech stack:** Node.js >=18 ESM, built-in net/fs/crypto/child_process,
playwright-core and the already installed MCP SDK; no new dependency.

## Global constraints

- One user, several clients, existing dedicated Edge profile and ChatGPT login.
- Two simultaneous generations by default; configure IMAGE_GEN_MAX_PARALLEL.
- Same-tab jobs run FIFO; different tabs may overlap.
- Stable browser target IDs, never array indices; no implicit first-tab reuse.
- A timeout or missing current result fails without substituting an old image.
- Profile data, cookies, prompts, runtime records and generated files stay out
  of Git. Preserve the upstream license and attribution.
- No unauthenticated TCP listener; IPC requests authenticate with a runtime
  secret protected by the user's local file permissions.
- Keep legacy image-gen-mcp / mcp-server.mjs configurations operational.

## Shared interfaces

The browser driver exports `BrowserDriver` from `browser-driver.mjs`:

```js
const driver = new BrowserDriver();
await driver.listTabs(); // [{tab_id, title, url, managed}]
await driver.createTab({ name: "hero" }); // same TabInfo
await driver.run(job, { signal, onStage }); // result metadata
await driver.cancel(job); // resolve only when stopping is acknowledged
await driver.close(); // disconnect; do not close Edge or unrelated tabs
```

The job record passed to `run` includes `job_id`, `tab_id`, `prompt`,
`artifact_path`, `output_path`, `transparent_background`, and
`reference_images`. The driver saves only to `artifact_path`; the engine
atomically exports the immutable result to `output_path` before success.

The IPC client exports `request(method, params = {}, options = {})` from
`coordinator-client.mjs`. `options` supports `timeoutMs` and `autoStart`.
Methods: `ping`, `list_tabs`, `create_tab`, `start_generation`, `get_job`,
`list_jobs`, `wait_job`, `cancel_job`. Job lookup/cancel params use `job_id`.
`wait_job` uses bounded `timeout_ms` (default 30 seconds) and may return an
unfinished job; adapters repeat waits as necessary. It never resubmits work.

`start_generation` accepts `{prompt, tab_id?, new_tab?, output_path?,
output_dir?, filename?, transparent_background?, reference_images?}`.
Omitting the target creates a fresh tab. `tab_id` and `new_tab: true` conflict.
Prompt and path validation belongs in the engine, not just adapters.
Job statuses are `queued`, `running`, `succeeded`, `failed`, `cancelled`.
Every job response includes `job_id`, `tab_id`, `status`, `output_path`,
timestamps and, when terminal, `result` or `error`. Results include
`artifact_path` so callers never reread another job's overwritten export.
